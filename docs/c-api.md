# C ABI contract

The `thouless-capi` crate is the language-neutral boundary to the same Rust
scientific core used by the Rust and Python APIs. Its contract version is
`1.1`, encoded as `major << 16 | minor` by `thouless_abi_version()`. A change
that removes or changes a public function, structure layout, status meaning,
ownership rule, or numerical convention must increment the ABI major version.
Additive functions and status values increment the minor version.

`crates/thouless-capi/include/thouless.h` is generated by
`tools/generate_c_header.py`. CI rejects a stale header, checks that the header
and Rust library export the same functions, and compiles a C11 client against
the built dynamic library.

## Values and arrays

- Scientific real and complex values use binary64 precision.
- `ThoulessComplex64` stores real and imaginary `double` components.
- Matrix and rank-three tensor views carry element strides. Contiguous
  row-major and column-major arrays are both valid; byte strides are not.
- Inputs are borrowed only for the duration of a call. The library does not
  retain array pointers.
- Every non-null pointer must address the documented readable or writable
  extent. The Rust declarations are therefore `unsafe extern "C"`; C and Julia
  callers carry the same obligation even though their syntax has no `unsafe`
  keyword.
- Outputs use caller-owned storage. A size-query operation reports the required
  count and returns `THOULESS_BUFFER_TOO_SMALL`; no hidden allocator has to be
  paired across the ABI.
- Momentum conventions are operation-specific and match the Rust API:
  `Model` accepts reduced reciprocal coordinates, while `thouless_bloch_phase`
  and lead-band functions accept the phase angle used in `exp(i R k)`.

## Handles and ownership

Builder and model handles are created by the corresponding creation operation
and destroyed exactly once by `thouless_model_builder_destroy` or
`thouless_model_destroy`. Passing null to a destroy operation is a no-op.
Building consumes the scientific contents of a builder but not its allocation,
so the builder handle must still be destroyed.

Immutable model handles permit concurrent read-only calls. Builder mutation
requires exclusive access. Caller-owned input and output arrays must not be
mutated concurrently with a call.

## Errors and panic containment

Every fallible operation returns a stable `ThoulessStatus`. A non-success
status records a UTF-8 diagnostic in thread-local storage. Query it with
`thouless_last_error_length`, allocate `length + 1` bytes, then call
`thouless_last_error_copy`. The message remains valid independently of other
threads.

Every exported fallible function contains Rust unwinding. A Rust panic becomes
`THOULESS_PANIC` and never crosses the C boundary.

## Building

```bash
cargo build --release -p thouless-capi
python tools/generate_c_header.py --check
python tools/run_c_smoke.py --profile release
```

Release archives place the generated header beside the platform dynamic
library.

## Native derivatives

`thouless_ad_affine_projector_value_and_grad` evaluates an affine Hermitian
Hamiltonian, a gauge-invariant occupied-projector objective, and its physical
parameter gradient in the Rust core. It is the C/Julia boundary to the same
VJP used by the Rust and Python APIs; the ABI never evaluates finite
differences. See `docs/native-ad.md` for the mathematical convention and
coverage boundary.
