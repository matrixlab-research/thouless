# Native automatic differentiation

Thouless treats first-order derivatives as scientific operations. The Rust
core owns parameter semantics, mathematical pullbacks, convergence failures,
and complex-number conventions. Python, Julia, and C bindings only convert
data and call those Rust operations.

Finite differences in `thouless::differentiation` remain independent
validation oracles. No value returned by `thouless::ad` is produced by finite
differences.

## Convention and protocol

The public rule protocol is `chainrules-core 0.2`. A differentiable input has
separate tangent and cotangent types, and a VJP returns a one-shot pullback.
For complex vectors and matrices, every rule uses the real pairing

```text
dL = Re tr(G† dX).
```

`ModelParameters`, `ModelDirection`, and `ModelGradient` contain independent
real physical coordinates. Hermitian conjugates and sparse matrix entries are
generated by the parameterization; gradients are contracted directly back
into those coordinates.

The workspace minimum supported Rust version is 1.85.

## Implemented native rules

`thouless::ad` currently provides:

- dense and sparse affine Hermitian parameterizations;
- forward and adjoint matrix-free action for dense matrices, CSR matrices,
  and bound sparse parameterized operators;
- analytic parameter JVP and VJP contractions without an ambient matrix
  Jacobian;
- the mathematical JVP and VJP of a dense complex linear solve;
- Feynman-Hellmann derivatives for isolated eigenvalues;
- gauge-invariant derivatives of separated occupied projectors;
- a periodic quantum-metric mesh objective;
- an implicit surface Green-function rule derived from the converged Dyson
  equation, without reversing López-Sancho iterations;
- an analytic fixed-self-energy Caroli-transmission objective;
- a complete device-and-periodic-lead transmission VJP covering device and
  lead Hamiltonians, periodic hoppings, rectangular interface couplings,
  energy, and broadening;
- a matrix-free sparse GMRES objective using one primal and one adjoint solve,
  with independent true-residual diagnostics;
- a sparse KPM scalar objective with checkpointed reverse recurrence.

The surface rule solves the linearized equation

```text
g^-1 dg g^-1 - V dg V†
  = dH + dV g V† + V g dV† - dz I.
```

Its pullback solves the adjoint equation once and differentiates the cell
Hamiltonian, periodic hopping, energy, and broadening. Failure of the primal
surface solve, singularity of the linearization, or a non-finite derivative is
reported as `AdError`.

The KPM pullback never materializes a dense Hamiltonian. For `N` moments,
dimension `D`, and checkpoint interval `K`, it retains
`O((N/K + K)D)` complex state rather than an `O(ND)` tape. The report separates
primal, recomputed, and adjoint operator applications and records the peak
number of retained vectors.

## Rust example

```rust
use thouless::ad::{
    AffineHermitianFamily, ModelParameters, SpectralProjectorObjective,
};
use thouless::ComplexMatrix;

# fn run(
#   base: ComplexMatrix,
#   directions: Vec<ComplexMatrix>,
#   target: ComplexMatrix,
# ) -> Result<(), thouless::ad::AdError> {
let family = AffineHermitianFamily::new(base, directions)?;
let objective = SpectralProjectorObjective::new(&family, 1, target, 1.0e-8)?;
let parameters = ModelParameters::new(vec![0.1, -0.05, 0.08])?;
let (value, gradient) = objective.value_and_grad(&parameters)?;
# let _ = (value, gradient);
# Ok(())
# }
```

Scalar objectives expose direct `value`, `jvp`, and `value_and_grad` methods
and also implement the corresponding `chainrules-core` traits.

## Python and Julia

Python calls the Rust projector VJP:

```python
from thouless import ad

value, gradient = ad.affine_projector_value_and_grad(
    base,
    directions,
    parameters,
    occupied=1,
    target=target_projector,
)
```

Julia uses the same Rust function through the C ABI:

```julia
result = Thouless.AD.affine_projector_value_and_grad(
    base,
    directions,
    parameters;
    occupied=1,
    target=target_projector,
)
```

The C entry point is
`thouless_ad_affine_projector_value_and_grad`. All three interfaces share
Rust values, gradients, gap checks, and error behavior.

## Correctness and advantage gates

`tests/native_ad.rs` checks central finite differences, JVP/VJP adjoint
identities, Feynman-Hellmann, basis and projector invariance, sparse adjoint
action, surface implicit derivatives, quantum-metric gradients, and
checkpointed KPM reverse mode.

`examples/native_ad_benchmark.rs` compares native reverse mode with central
finite differences at 48 physical parameters. On the initial Apple Silicon
release run:

| Workflow | Native | Central difference | Speedup | Maximum relative error |
|---|---:|---:|---:|---:|
| Occupied-projector objective | 107 us | 7,720 us | 72.2x | 5.32e-11 |
| Sparse KPM objective | 567 us | 17,020 us | 30.0x | 7.22e-10 |

The spectral calculation uses one native eigensystem instead of 96
finite-difference eigensystems. The KPM calculation uses 211 total primal,
recomputed, and adjoint operator actions instead of 6,816 finite-difference
actions. Checkpointing retains at most 26 state vectors instead of a 72-vector
full tape.

Wall-clock results depend on hardware. CI therefore stores the raw JSONL
artifact and gates four independent properties:

1. analytic-gradient accuracy;
2. eigensystem or sparse-operator application reduction;
3. checkpoint memory reduction;
4. a conservative measured speedup over central differences.

Run the same gate locally with:

```bash
cargo run --release --quiet --example native_ad_benchmark \
  > native-ad-benchmark.jsonl
python tools/check_native_ad_benchmark.py native-ad-benchmark.jsonl
```

## Validity boundaries and remaining work

An isolated eigenvalue or occupied projector is differentiable only while its
declared separating gap remains open. Mesh shape, sparse structure, random
seed, subspace rank, solver branch, and connectivity are discrete. They are
not silently assigned zero derivatives.

The detailed requirement audit is `spec/coverage/native-ad.toml`. The overall
AD status remains `Incomplete`. The principal open boundaries are:

- full physical parameter templates for geometry, fields, nonlinear
  hoppings, leads, and interfaces;
- reusable sparse factorization or preconditioner state across primal and
  adjoint solves;
- an implicit Wannier/localization stationarity rule;
- derivative bindings beyond the affine-projector reference workflow;
- production-scale, disorder-held-out, and isolated evaluator tests.

These gaps remain tracked by
[Thouless issue 13](https://github.com/matrixlab-research/thouless/issues/13)
and the evaluator-owned held-out issue referenced by the coverage file.
